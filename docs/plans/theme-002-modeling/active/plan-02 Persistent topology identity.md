# Persistent topology identity

## Purpose

Let models refer to earlier faces and edges through edits, and use those references safely in calculations and later operations. [Owners](../../OWNERS.md).

## Scope and completion criteria

- [x] Establish an exact, deliberately limited identity case for one explicitly named box, including resizing, translation and scaling; expose current face/edge data and identity resolution.
- [ ] Define stable graph feature and instance identities, including duplicate handling and repeated module instances.
- [ ] Obtain and compose trustworthy operation provenance for Boolean cuts, joins, splits and blends. Report missing, split, merged or ambiguous references explicitly; never silently select a nearby entity.
- [ ] Allow supported identities to drive later geometry operations and calculations. Verify changes to input dimensions, split/merge cases, transforms, repeated instances and vanished features.
- [ ] Validate the resulting behavior against the adapter and document which operations carry exact identity.

## Current state

- Status: active. Named box identities propagate through supported graph operations using same-body SolidCore provenance; named instances distinguish repeated parts. Reference-selected fillets and chamfers use the evaluated body's ordered edges.
- Current next action: finish the chained uncertainty fix, review the final diff and rerun affected checks. Investigate an audited kernel history contract for definitive deletion and generated-entity attribution.
- Known tracked references with no observed descendant are reported as deleted or untracked. Untagged output is generated or untracked. The current kernel interface cannot certify which; do not present these as definitive deletion or generation.
- The versioned patch exposes ordered provenance on the pinned SolidCore. The adapter's cut-generated chamfer edge has no identity and remains point-selected. See `docs/feature-tracking.md` and the handover for supported cases, evidence and limitations.
