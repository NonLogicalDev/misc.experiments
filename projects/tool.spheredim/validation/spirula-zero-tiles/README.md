# Bilateral tile regression harness

This isolated macOS Vulkan harness dispatches only Spirula Studio's `bilagrid_ppisp_bwd_tile` entry. It does not build the trainer or replace its renderer. Use the layerctl-pinned Spirula source and the separate experimental layer in `vendor/spirula-studio/layers/0004-zero-gradient-tiles`; never edit the generated projection as the durable patch. The baseline must use the same pinned source without that layer.

Compile the original and patched entry separately with the pinned Slang compiler and the include paths and flags in the project's generated `ss_spirv_blobs` build rules. Include both the base and `SS_NATIVE_F32_ATOMIC_ADD` variants in each embedded registry; MoltenVK on the tested Apple M2 Pro selected the native atomic variant. `spirv_tool embed <output.cpp> --list <blob-list>` creates each registry. Keep compiled files outside the repository.

Configure this directory separately for each registry with `SPIRULA_SOURCE`, `MOLTENVK_ROOT`, `I18N_LIBRARY`, and `SPIRV_EMBED` set to the pinned Spirula source, unpacked MoltenVK root, built Spirula i18n static library, and generated registry source. Build `spirula_zero_tiles` with at most two jobs and a storage guard. Each executable accepts an output filename and checks analytic zero-gradient behavior on GPU; compare the two outputs with `python3 compare.py BASELINE_OUTPUT CANDIDATE_OUTPUT`. The fixture also covers partial edge tiles, sparse and dense gradients, NaN input, and separate or aliased image-gradient buffers. This is same-device regression evidence for float32 and q16-grid/float16-RGB inputs, not an independent CPU reference.

Run `python3 benchmark.py BASELINE_EXECUTABLE CANDIDATE_EXECUTABLE NEW_RESULT.json` during a quiet GPU window. It measures q16 grid reads with float16 RGB at 1024×512 and 2048×1024. Modes 0, 1 and 2 are all-zero, synthetic half-frame zero, and all-active gradients. Each process warms up three dispatches and reports ten GPU timestamps; two process pairs alternate order. The driver checks for 35 GiB free before each process. The benchmark does not replay recorded gradients and does not establish end-to-end training speed or quality.

The first comparison on 2026-11-15 is invalid: reconfiguring one build directory reused the same embedded object, and both executable hashes were identical. Build baseline and candidate in separate directories and verify that their executable and shader hashes differ before comparing them. The corrected separate builds passed the float32 and q16-grid/float16-RGB parity fixtures. The production-format microbenchmark measured lower kernel time for synthetic zero and half-empty tiles and a small change for all-active tiles on the tested Apple M2 Pro. These are not end-to-end or q16 correctness results. The layer remains disabled pending further validation.

The optional `0005-macos-compact-spirv` layer adds `SS_MACOS_COMPACT_SPIRV=ON` for macOS source builds. It keeps the normal registry selection and emits assembler `.incbin` references instead of large C++ word arrays. Its default is off and it does not affect SfM or NN registries. Preserve an inventory with each compiled blob's path, byte count and SHA-256; `audit_macho_registry.py GENERATED_CPP EMBED_OBJECT INVENTORY.json` checks the capability-filtered entry set and compares every Mach-O object symbol's bytes with that inventory. The inventory has a top-level `blobs` array containing `path`, `bytes`, and `sha256` for each SPIR-V file.
