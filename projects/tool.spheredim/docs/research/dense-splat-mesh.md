# Native 360 dense, splat, and mesh reconstruction

The requirement is to process each full equirectangular frame as one spherical image, honor operator masks, and run on Apple and AMD GPUs. Frame sampling over time is allowed; extracting perspective views or cube faces is not.

- [Spirula Studio](https://github.com/harry7557558/spirula-studio) documents native equirectangular Gaussian training, Vulkan/MoltenVK, masks and mesh export. [Dataset conventions](https://github.com/harry7557558/spirula-studio/blob/master/docs/datasets.md) define equirectangular inputs and white-means-keep masks. The preset defaults can split panoramas: explicitly set both `--warp-spherical-to-pinhole 0` and `--warp-to-pinhole 0` and verify that camera counts do not increase. On the user's recording, a 14-panorama, three-iteration Apple M2 Pro smoke test confirmed native input and GPU execution; quality was not evaluated. The project is GPL-3.0.
- [Spirula dense reconstruction](https://github.com/harry7557558/spirula-studio/blob/master/docs/dense.md) documents `--matching-space source` and `--source-workflow true` to match original spherical images; its default rectified workflow extracts perspective views and is out of scope. The RoMa v2 checkpoint is separate and has additional terms; source matching and results have not yet been tested here.
- [DA360](https://github.com/antigravity-tech/DA360) is a direct panorama monocular depth model and may help initialize geometry, but its depth scale and temporal consistency need evaluation; Apple and AMD execution is unverified.
- [360MVSNet](https://jdily.github.io/proj_site/360mvsnet_proj.html) describes multi-frame spherical depth reconstruction. Released code and cross-vendor hardware support have not been established.
- [PanSplat](https://github.com/chengzhag/PanSplat) and [PFGS360](https://github.com/zcq15/PFGS360) are native-panorama Gaussian research approaches but document CUDA dependencies. They require porting before they satisfy the hardware requirement.

The current real clip is masked, with strong pose failures near 70 seconds. Held-out frames can test rendering but are not fully independent if the seed points or poses used them during tracking. Point density, splat appearance, and mesh accuracy must be measured separately on diverse scenes; none is established merely by exporting a file.

For the pinned release used in the Apple smoke test, `scripts/fetch-spirula.sh OUTPUT_DIRECTORY` downloads the official macOS ARM64 or Linux x86-64 Vulkan package and checks its SHA-256. Put downloads in a local artifact cache, not Git. Linux/AMD execution has not been tested. `scripts/export_spirula_dataset.py` creates original equirectangular training frames and explicit white-keep masks from matching 360DVO poses; it requires the user to provide a suitable `--mask-top` and does not detect people. Keep holdout frames separate from training and verify every relevant exclusion mask before reconstruction.

An experimental 3,000-step splat and mesh were produced from one recording, but visible holes and smearing mean the result does not meet the quality target. A full-checkpoint longer run is active. The small point cloud exported from the mesh is derived from that mesh; it is not an independently measured dense reconstruction.

`scripts/train_spirula.py` wraps the pinned trainer with masks enabled, both perspective-warp options disabled, a camera-count guard, full checkpoints, a local log and atomically written status JSON. It takes the executable, dataset, new run directory, new status file and new log file as arguments; use `uv run --script` or the project's uv-managed Python environment. The wrapper passed a three-step Apple GPU test on 14 full panoramas and rejected a simulated camera split. Check `--help` for limits and checkpoint interval. The count guard detects a backend that ignores the no-warp settings; it is not a substitute for auditing another backend's projection behavior.
