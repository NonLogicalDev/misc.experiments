# Spirula native equirectangular audit

Audited 2026-11-15 against the exact Spirula Studio `v2026.11.12` source commit [`667e353bca3941303a4d93e93aa8ae3f2c202712`](https://github.com/harry7557558/spirula-studio/tree/667e353bca3941303a4d93e93aa8ae3f2c202712), which the tested executable identifies as `2026.11.12 (667e353)`. The initial source checkout at `512c4bf` is a later revision and is not the basis of these code claims. CUDA and Vulkan are separate backends; the existing run was Vulkan/MoltenVK on Apple M2 Pro. AMD runtime behavior is not measured.

## Existing evidence

The preserved 10,000-step run trained 120 full 1024×512 equirectangular cameras, with 120 reported after splitting, explicit `warp_spherical_to_pinhole=0`, `warp_to_pinhole=0`, and a 500,000-splat cap. It used the older broad mask; it is not a clean-mask quality result. The 18 holdouts are independent of splat fitting, not of pose/seed estimation. All 138 saved camera-to-world matrices reconstructed from exported COLMAP pose text match the original dataset manifest within 4.45e-15 in float64; shared train/eval poses match exactly. Seven checked source video frames match the saved area-resized PNGs pixel for pixel. Those checks do not establish that the original poses are correct.

Independent measurement of the 18 saved holdout render PNGs and saved white-keep masks gave mean unaligned, masked RGB PSNR 20.611 dB, reproducing the trainer's 20.612 dB within rounding. Weighting each latitude by spherical area gives 20.218 dB. Mean render/reference grayscale gradient-magnitude ratio was 0.704; the weakest frame 00015 was 13.39 dB area-weighted PSNR with a 0.27 gradient ratio. These are image-space diagnostics, not geometry accuracy or proof of blur causation. Existing saved checkpoint/eval-camera appearance and train-frame-scale caveats remain; no new reconstruction was run.

On these saved images, the mean absolute first-versus-last-column RGB difference over valid paired pixels was 13.03/255 in rendered images versus 3.79/255 in the reference; the render exceeded the reference in all 18 views. As a local control, render columns 0 and 1 differ by 2.53/255 on average. This is an observed boundary discontinuity, but does not prove which implementation fault caused it.

## Release source findings

1. **Raster seam — source-level defect; real seam symptom observed, causal attribution unproved.** The ordinary 3DGS spherical projection emits one axis-aligned rectangle around each projected Gaussian ([primitive projection, lines 553–571](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/shaders/primitive_3dgs.slang#L553-L571)). Vulkan packs that AABB with both x bounds clamped to `[0,W]` ([aabb16, lines 8–18](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/aabb16.slang#L8-L18)), clamps tile ranges to the image ([tile intersection, lines 110–120](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/intersect_tile.slang#L110-L120)), and evaluates an ordinary unwrapped `mean_x-pixel_x` ([raster forward, lines 206–219](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/rasterize_fwd.slang#L206-L219)). A Gaussian straddling longitude zero cannot contribute its clipped footprint to the opposite edge in this path. The unscented projection unwraps sigma-point longitudes before covariance calculation, but that is distinct from periodic raster coverage ([primitive, lines 356–380](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/shaders/primitive_3dgs.slang#L356-L380)). Implement wrap-aware intersection and raster offsets; cover gradients, duplicate prevention and splats wider than one period. Confirm the backend path and execute a single-Gaussian seam regression before claiming runtime causation.

2. **Calibration warp seam — exact source branch reproduced on CPU, not yet GPU-tested.** For an x sample crossing the ERP edge, Vulkan substitutes the render for target RGB ([calib warp, lines 164–176](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/calib_warp.slang#L164-L176)); its mask branch treats the outside x coordinate as invalid ([lines 488–500](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/calib_warp.slang#L488-L500)). Even in-bounds cubic samples clamp off-edge taps ([lines 103–106 and 126–143](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/calib_warp.slang#L103-L143)). `validation/spirula-erp/calib_seam_oracle.py` is a minimal transcription with concrete numeric checks, not a Vulkan execution. The existing run enabled `use_calib_warp=true`; its 120×9×9×2 saved parameter values are nonzero. Periodic sampling, mask semantics, parameter-grid continuity and backpropagation must be validated together; do not assume this is the sole blur cause.

3. **Depth/normal support — guarded limitation, not a demonstrated failure of the current run.** In this release direct equirectangular training explicitly rejects actual loaded depth or normal supervision ([TrainerCore, lines 1151–1159](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/app/TrainerCore.cpp#L1151-L1159)). The tested dataset has no depth or normal directories; its nonzero normal-supervision setting did not supply real normal measurements. Projection output is radial distance (`length(mean_c)`) and ERP sorting uses squared radial distance ([projection](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/shaders/primitive_3dgs.slang#L433-L438), [sorting](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/shaders/projection_utils.slang#L986-L995)). The shared pixel-wise unprojection has an explicit ERP unit-ray branch ([pixel-wise, lines 303–340](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/shaders/pixel_wise.slang#L303-L340)), but the Vulkan depth-normal stencil explicitly zeroes first and last image columns and its backward ignores wrapped neighbors ([forward](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/pixel_wise_render.slang#L194-L229), [backward](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/pixel_wise_train.slang#L259-L275)). This is a code-level seam limitation for future native depth/normal work, not evidence the current RGB training invoked that supervision.

4. **Area weighting and losses — confirmed settings/implementation, quality impact is an experiment.** RGB loss is multiplied by binary validity at the pixel level ([per-pixel loss](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/shaders/per_pixel_losses.slang#L158-L189)); this path does not express per-latitude solid-angle weighting. That is not automatically a bug unless equal-sphere weighting is the chosen objective. Masked SSIM computes neighborhood coverage ([coverage implementation](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/fused_ssim.slang#L130-L159)) rather than simply using a center mask; verify complete neighborhood and backward semantics with numerical tests. Its out-of-range samples are zero and masks count outside pixels as valid ([lines 90–103](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/fused_ssim.slang#L90-L103)), so longitude-periodic SSIM needs explicit testing. The run used `ssim_blur_tolerant`; upstream describes its asymmetric 1.5-pixel blur comparison, intended to tolerate blurry photos rather than reward blurry renders ([release note](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/docs/notes/ssim-blur-tolerance.md)). Compare standard versus blur-tolerant SSIM; do not assume the latter caused the observed blur.

5. **Numerics near poles and visibility — test before declaring defects.** Analytic Gaussian projection pushes covariance through the ERP angular Jacobian ([primitive, lines 194–210](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/shaders/primitive_3dgs.slang#L194-L210)); longitude is undefined at the poles, and near-pole covariance and derivatives require explicit finite and continuity checks. Center-depth sorting is not the same as per-ray ordering for large intersecting anisotropic Gaussians. The release has native ERP projection/render backend parity tests, but matching two backends does not prove correct seam behavior; compare with an independent full-sphere reference.

## Minimum Terra renderer acceptance

- Establish a CPU double-precision spherical reference and synthetic scene with one splat centered just on either side of the seam. Compare each edge pixel and gradients against a shifted copy whose seam is elsewhere. Include Gaussian footprints narrower than a tile, wider than a tile and wider than the image, and check that wrapped tile duplication never blends the same splat twice in one pixel. Run forward and backward on Vulkan/MoltenVK; compare to CPU. Repeat on AMD before claiming AMD support.
- Exercise calibration warp with fractional negative/positive flows at `x=0` and `x=W-1`; check periodic cubic taps even when the sampling center remains inside the image. Check both RGB and masks, partial masks, backward finite differences and periodic learned control fields. Pole crossings need a spherical reflection plus half-turn of longitude, or an explicit invalidity policy; a simple x wrap is insufficient there.
- Use known analytic ERP sphere and plane scenes to test camera conventions, radial depth, normals, pole limits, occlusion ordering and the exact frame transform. Validate both `3dgs` and `3dgut` only if both are claimed. Never use perspective crops as the reference input.
- Test masked SSIM and RGB loss on nonrectangular masks, tiny/all-masked windows, seam-crossing masks and arbitrary changes under excluded pixels; verify both loss and gradient invariance and no NaNs. Make spherical-area weighting an explicit controlled option for training and for reporting; normalize by valid weighted area and compare backend results against CPU.
- Train a bounded A/B on identical verified frames, masks, poses, seed, timestep split, image resolution and random seed. Compare raw holdout per-frame and per-latitude errors, seam strips and edge contrast plus paired visual crops. Vary only one of seam fix, calibration warp, appearance, SSIM or resolution at a time. Re-run promising changes across seeds and scenes. Holdout poses/seed that used those frames are not independently estimated truth.

## Follow-up: masked SSIM and calibration footprint

The mask applies to the **SSIM neighborhood**, not only its center. The release Vulkan shader zeroes each masked input tap before moment convolution ([fused SSIM, lines 239–251](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/fused_ssim.slang#L239-L251)), divides local moments by Gaussian-weighted valid coverage ([lines 317–332](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/fused_ssim.slang#L317-L332)), and suppresses gradients from masked centers and at masked destination pixels ([lines 375–386](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/fused_ssim.slang#L375-L386), [lines 437–447](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/fused_ssim.slang#L437-L447)). Blur-tolerant SSIM additionally uses a normalized masked blur and masks its adjoint ([lines 1254–1270 and 1303–1312](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/fused_ssim.slang#L1254-L1270)). Upstream tests check finite differences at a mask boundary and zero gradient for masked pixels ([mask tests](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/tests/mask_loss_semantics.cpp#L452-L495)). Those tests do not by themselves prove correctness of the **preceding calibration warp**.

The release calibration RGB warp's 4×4 cubic tap loader does not consult the input mask, while the separately warped mask checks the original center and nearest warped center, not the full RGB interpolation footprint ([RGB sampling](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/calib_warp.slang#L103-L143), [nearest mask](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/calib_warp.slang#L488-L500)). A CPU transcription in `validation/spirula-erp/calib_seam_oracle.py` gives a valid output at row 4 + 0.25 pixel whose nearest mask remains valid, but changing a masked tap at row 3 from 0 to 1 changes the target from 0.333594 to 0.263281. This demonstrates a source-level masked-footprint dependency, **not** execution on the GPU or measured contamination magnitude in this video. With a pre-blacked input, the dependency can introduce an artificial border rather than leaking the actual operator. A first safe fix is to reject supervision when any nonzero-weight interpolation tap is invalid; a mask-aware renormalized cubic alternative needs careful treatment of negative kernel weights, anti-ringing bounds and gradients.

The SSIM scalar/gradient normalize by the entire `B×W×H`, treating masked centers as score 1 ([SSIM, lines 231–232 and 357–365](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/fused_ssim.slang#L225-L232)); RGB loss divides by valid `MaskTotal` ([RGB normalization](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/shaders/per_pixel_losses.slang#L375-L384)). Thus changing valid area changes effective SSIM-versus-RGB weighting. This is a verified normalization choice, not evidence of a specific quality regression. When testing sphere-area weighting, explicitly decide whether each frame or each valid solid angle contributes equal weight; test 25%, 50%, and 100% valid masks with the same controlled residual, and compare raw and weighted gradient norms.

**Focused backend regression:** construct 2:1 RGB and mask textures with an excluded black/white strip and a smoothly varying valid region; set a subpixel warp so the output center and nearest warped center remain white while its cubic footprint touches the excluded strip. Render twice, changing only values in the excluded strip. For both plain and blur-tolerant SSIM, assert identical valid warped samples, scalar loss, valid-pixel RGB gradients, and warp gradients within stated FP precision. Repeat at ERP longitude seam and for all-masked neighborhoods. Use an independent CPU reference plus Vulkan, then the same on actual AMD; verify pinhole paths are unchanged. The existing CUDA-oriented and cross-backend tests are useful references, not proof that this case passes on Metal or AMD.

## Research relevance and sequencing

- [3DGUT (CVPR 2025)](https://openaccess.thecvf.com/content/CVPR2025/papers/Wu_3DGUT_Enabling_Distorted_Cameras_and_Secondary_Rays_in_Gaussian_Splatting_CVPR_2025_paper.pdf) motivates unscented nonlinear projection and per-ray evaluation; this release already has a `3dgut` ERP path. Its existence is not proof that periodic tile coverage or pole gradients are correct. First make both reference and existing `3dgs` seam tests pass; only then run controlled `3dgs`/`3dgut` A/B with identical input, seed and budgets.
- [Mip-Splatting (CVPR 2024)](https://openaccess.thecvf.com/content/CVPR2024/html/Yu_Mip-Splatting_Alias-free_3D_Gaussian_Splatting_CVPR_2024_paper.html) motivates separating image sampling/filtering from scene capacity. The recorded 1024×512 training input came from 2048×1024 footage; downsample/upsample probes lose measurable edge energy. First fix correspondence and boundary correctness, then compare resolution and antialiasing as a single-variable experiment; a bigger image alone cannot repair wrong poses.
- [PanoGS-SLAM](https://arxiv.org/abs/2609.17387) motivates sphere-consistent photometric weighting and depth-guided mapping. Treat it as a research comparison: its dataset, depth initializer and metrics differ, and neither its score nor hardware portability establishes a result here. Implement solid-angle weighting behind a switch with a CPU oracle; report raw as well as weighted metrics and compare quality at the equator, poles and mask boundary.

Plan 04's dependency order is sound: reproducible masks and pose-quality gates precede renderer fixes, depth and mesh work. Strengthen step 3 with the exact cubic-mask contamination and loss-normalization tests above, and treat existing mask SSIM checks as a base rather than presuming all masked neighborhoods are broken. Before any 10k run, run the one-splat seam/gradient and warp/mask proofs; then ablate one setting per short controlled run. Do not use per-frame fitted alignment or color correction as the main score, and do not promote a no-warp/SSIM setting solely on average PSNR.

Use bounded parallelism, estimate disk first, and do not clean an active build. ## Checkpoint calibration-field relevance

This is a CPU replay of the release's [`cw_cell` and `cw_flow`](https://github.com/harry7557558/spirula-studio/blob/667e353bca3941303a4d93e93aa8ae3f2c202712/src/backend/vulkan/shaders/calib_warp.slang#L59-L100) math, not an execution of the Vulkan shader. The saved 10k checkpoint's `eng.calib_warp.params.npy` contains 19,440 finite scalars, matching 120 cameras × 9 × 9 control points × 2 axes. With the run's 1024-pixel ERP width and `fx=1024/(2π)`, absolute horizontal control-point displacement is 0.343 px median, 1.375 px p90, and 3.199 px p99. Using the original keep-mask rows 207–511 and evaluating the bilinear field at the boundary pixel centers, x flow points out of bounds at the left edge for 33.54% of camera-row samples, with at least one such row in 87/120 cameras. At the right edge it points out of bounds for 45.77%, with at least one such row in 92/120 cameras.

These counts establish that nonzero boundary-directed fields are present under the code's pixel-flow convention; they do not prove how many contributions survived every runtime masking condition, independently execute the GPU code, or establish the amount of blur caused. The saved inputs use the old broad masks and are evidence for diagnosing this checkpoint only.

### Bounded renderer diagnostic

The retained 1024 dense 6k/7k and native-2048 SfM 7k runs use `primitive=3dgs`, SH degree 3 without warmup, and enable the bilateral grid and PPISP. The mounted release exposes `--primitive 3dgut`; selecting it needs no build. Its ERP sigma-point projection handles nonlinear longitude locally, but that is not a periodic raster fix. The Apple/Vulkan single-splat fixture found half-opacity loss at the seam in both stock primitives; the 28 passing baseline finite-difference checks do not establish periodic, wide-footprint or pole correctness.

A small proposed diagnostic would render the existing three-capture group at zero updates from the same original 7k PLY with appearance correction disabled and `--primitive 3dgut --steps-per-save 0`, then compare the same source pixels to the retained 3DGS zero renders. It would isolate a renderer change for fixed imported parameters, not compare fully optimized reconstructions or distinguish undertraining from representation limits. Run only under a 15 MB output and 120 second guard after task-wide storage and GPU checks; no result is claimed here. If the result merits follow-up, a paired, matched fitting experiment is necessary, with the seam limitation retained in its interpretation.
