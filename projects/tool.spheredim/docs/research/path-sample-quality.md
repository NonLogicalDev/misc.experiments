# Native ERP path sample quality

These saved 3,000-step SfM and DVO renders do not meet the requested visual bar. The full-panorama sheet shows blurred doorframes, missing picture and wall detail, and displaced/ghosted objects, including at the best measured sample. This is evidence about the saved model at camera poses, separate from viewer rendering. It does not establish which defect caused the loss.

The paired runs used 133 1024×512 full equirectangular images from the 2048×1024 stabilized source; 116 were used for training and 17 held out, although all contributed to the SfM poses and seed. Both used 3,000 steps, the same source pixels, split, masks and SfM seed. The DVO arm used one global similarity transform into the SfM frame. Calibration warp and blur-tolerant SSIM were enabled. No fitted per-frame spatial or color adjustment is applied in these measurements.

The saved SfM and DVO ground truths and masks are equal. Each ground-truth image matches the corresponding dataset image exactly at every valid eval-mask pixel. Eval index i corresponds to manifest name index 8i (0-based). The eval masks exclude 2,365–3,696 more pixels than the dataset masks per image; measurements use the saved eval masks. The JSON lists all 17 exact source frame numbers and timestamps from the source review manifest and per-arm metrics. For reference: worst SfM is frame 1995 at 66.5665 s (13.70 dB area-weighted PSNR); median is frame 840 at 28.028 s (21.09 dB); best is frame 240 at 8.008 s (24.49 dB). The sheet orders those three cases worst, median, best, with reference, SfM and DVO rows for each.

Mean masked spherical-area-weighted PSNR over 17 samples: SfM 20.78 dB, DVO 18.44 dB. Mean render/reference gradient magnitude ratio: 0.575 and 0.360 respectively. The ratio indicates lost edge energy but is not a direct sharpness or geometry score. The 10k old viewer checkpoint is a different model with broader masks; these results do not establish its training-view quality or whether viewer position/orientation matches a source frame. Existing CLI output contains no saved training-view renders.

The next controlled experiment must render original training cameras at their exact input poses using the unchanged checkpoint and report training and held-out samples separately. The executable's evaluation split is applied during dataset load, and the checkpoint includes per-camera calibration state: simply changing the split on resume risks changing camera indices and cannot be assumed equivalent. Preserve and check camera identity, per-camera state, and no extra optimization before accepting those images. After correspondence is proven, compare one change at a time: a fixed-projector/no-calibration-warp run and the native seam correction have concrete testable rationales; a 2048 input run then measures resolution loss. These are hypotheses, not established causes.

The current viewer uses the older 10k checkpoint and `tracking/poses.json`; its `world_from_train` matrix is identity. Comparing all 138 old dataset manifest poses to the current viewer trajectory at the exact same timestamps, 137 matrices match exactly. Frame 2055 differs by 0.001244 tracking units in position and at most 0.000900 in a rotation-matrix element. This rules out a large position-transform mismatch at these sampled times, not unsampled trajectory positions or a matched rendered view. The viewer retains look orientation while scrubbing. The old dataset manifest names `panorama-camera-relative-masked-revised.mp4`; the current viewer reference names `panorama-horizon-stable-mask-ready.mp4`. Matching reference orientation therefore requires the stabilization transform as well as timestamp and position.

## Reproducing the measurements and viewer profile

`scripts/check_path_sample_quality.py` takes the SfM dataset, reviewed mask manifest, SfM run, DVO run, and a new output directory. It checks the saved evaluation pixels against the corresponding source dataset image at every valid pixel, checks that both arms use identical references and masks, and writes frame metrics and the worst/median/best contact sheet. It requires NumPy and OpenCV. With the reviewed recording root as `RECORDING`, run it from the project root:

```sh
uv run --with numpy --with opencv-python-headless python scripts/check_path_sample_quality.py "$RECORDING/sfm-tight-2hz/pose-comparison/sfm-dataset" "$RECORDING/operator-mask-reviewed-2hz/manifest.json" "$RECORDING/sfm-tight-2hz/pose-comparison/runs/sfm" "$RECORDING/sfm-tight-2hz/pose-comparison/runs/dvo" /path/to/new-output
```

`scripts/export_sfm_viewer.py` produces a separate candidate state and camera list from the SfM dataset, its run, the reviewed manifest and its source video. It retains source frame and timestamp for each camera and uses the run's recorded scene transform. The saved candidate is `sfm-tight-2hz/pose-comparison/sfm-viewer-profile-v2/viewer-state.json`; the running viewer was not changed. It has all 133 selected poses, including 17 evaluation frames, and makes no claim of acceptable reconstruction quality. Its complete 3×4 camera-to-world matrices were compared with pycolmap's independent quaternion rotation for each corresponding COLMAP record: maximum absolute difference was 2.23e-16. The viewer's actual state reader loaded all 133 poses, the checkpoint, the identity scene transform and the stabilized reference successfully. The viewer preserves orientation while scrubbing, so this profile alone does not establish a pixel-aligned view at every frame.

```sh
uv run python scripts/export_sfm_viewer.py "$RECORDING/sfm-tight-2hz/pose-comparison/sfm-dataset" "$RECORDING/sfm-tight-2hz/pose-comparison/runs/sfm" "$RECORDING/operator-mask-reviewed-2hz/manifest.json" "$RECORDING/panorama-horizon-stable-mask-ready.mp4" /path/to/new-profile
```

Focused checks: `uv run python -m unittest discover -s tests -p 'test_export_sfm_viewer.py'` and `uv run --with numpy --with opencv-python-headless python -m unittest discover -s tests -p 'test_check_path_sample_quality.py'`. The quality script was run against the saved data and reproduced the previous 17 per-frame results exactly.

The profile uses the normalized mean of the 133 camera-to-world negative Y axes for viewer up: `[0.061663, -0.019207, 0.997912]`. Angular departures have median 2.34 degrees, p90 4.45 degrees and maximum 39.54 degrees; source frames 1320, 1335 and 1800 are the largest outliers (39.54, 29.78 and 20.72 degrees). This is a scene-level estimate, not proof of each camera orientation. The profile includes the 22,774-point SfM seed in the same world frame. The state uses relative paths for artifacts under the recording.

## Controlled pose-exclusion preparation

A separate dataset for a fresh three-camera exclusion experiment is prepared at `sfm-tight-2hz/pose-comparison/sfm-exclusion-ab-dataset` beside the recording. It excludes training frames 1320, 1335 and 1800. Images, unchanged masks and the seed are symlinked, not copied. The 130 renamed paths deliberately sort so the original 17 held-out source frames remain at indices 0, 8, …, 128; the manifest maps every renamed camera to its original name, COLMAP image ID, source frame, timestamp and split. The source parser sorts image paths before the interval split, and the prepared directory was checked against that ordering. An actual trainer loader run has not yet been performed.

`scripts/prepare_pose_exclusion_ab.py` builds the dataset and records a command template and input hashes. No training was launched. At preparation, the dataset used 60 KiB; the prior 3,000-step run used 140 MiB and the volume had 46 GiB free. Allow additional working space for GPU buffers and output growth. The baseline saved only its latest full checkpoint. The comparison uses fresh training: camera indices and the 116-to-113-camera sampling schedule change, so a fixed seed does not ensure identical samples or GPU output. Removing these inputs is one controlled diagnostic, not a complete solution for those path positions.

A fully black mask was rejected as an unvalidated shortcut. The trainer's RGB loss normalizes by at least one valid pixel, but the PSNR calculation takes the logarithm of zero for an entirely masked image, yielding infinity; the view also remains in the uniform sampling schedule. Neither that metric nor optimizer and refinement behavior for this case has been established safe. The interval-8 quality comparison tool currently applies to the original paired datasets; use the derived manifest mapping to compare this reordered run's evaluation frames.

## Fresh no-warp pose-exclusion comparison

Two 3,000-step Apple GPU runs with calibration warp disabled, ordinary SSIM and no evaluation alignment compared the 116-camera baseline against the 113-camera exclusion, with the same 17 held-out source frames. Source reference images and masks matched exactly across all 17 saved pairs. Mean spherical-area-weighted PSNR was 20.768 versus 20.698 dB; pixel PSNR 21.295 versus 21.054 dB; masked SSIM 0.77405 versus 0.77283. Mean render/reference gradient magnitude was 0.542 versus 0.554; higher magnitude is not proof of correct detail. Weighted PSNR improved on 7/17 views. Both outputs remain visibly blurred and ghosted in the full ERP comparisons. This single seed does not establish variance or isolate camera exclusion from the changed sampling schedule.

The paired command manifest, progress, logs, checkpoints and comparisons are saved under the recording's `sfm-tight-2hz/pose-comparison/` directory. `scripts/run_pose_pair.py` monitors the disk budget and verifies training camera counts and saved settings; `scripts/compare_pose_pair.py` verifies frame identity and saved ground-truth/mask equality before scoring. The GPU runs stayed within the 2 GiB output and 35 GiB free-space limits. Existing renderer seam and mask-footprint tests remain open, and the held-out images contributed to SfM and seed estimation. Do not promote this result as a qualified model or as evidence that excluded cameras should be permanently discarded.
